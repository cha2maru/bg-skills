# bg-hidden-info-audit：漏れの点検

> **どこで使っても**：`bg` はプラグインが PATH に入れるコマンド（入れていない、このリポジトリの中なら `uv run bg`）。下の `examples/`・`specs/`・`src/`・`tests/`・`CLAUDE.md` は**プラグインのルート**（このスキルのディレクトリから 2 つ上）の中のファイル。コマンドの一覧は `<プラグインのルート>/CLAUDE.md` の「コマンド」の節。作る定義・対局は、利用者のプロジェクトに置く。

中身を伏せていても、送り手・件数・条件の文・番号の抜けから漏れる（人狼で見つかった 4 件。notes/loop の 19〜22 回）。下の表を、隠れた情報ごとに、見てはいけない人の立場で 1 つずつ確かめる。

## チェック表（見てはいけない人 Pn の立場で）

| # | 出力 | 確かめること |
|---|---|---|
| 1 | `bg show --as Pn`（`--compact` も） | 中身・種類・状態・属性が伏せられている。`known` は本人だけ |
| 2 | `bg log --as Pn` | 部品の ID・書いた値（`value`）・非公開の行為（`secret`）が出ない。件数も出ない |
| 3 | `bg candidates <行えないアクション> --by Pn` | 引数の条件の文から、隠れた値（役職など）が分からない |
| 4 | `bg act` の警告・エラー文（厳格・非厳格の両方） | 理由の文が隠れた値を含まない（提案の失敗など） |
| 5 | `bg undo` の出力 | 取り消した人の見え方で伏せられている |
| 6 | 発言（`talk`） | 内緒話の中身。夜（`whisper: hidden`）は送り手・宛先・件数・番号の抜けも |
| 7 | 指標（`metrics`）・知らせ（`signals`） | 隠れた値を読む指標・知らせがプレイヤーに出ない（`public: true` は公開の情報だけ） |
| 8 | 終わりの判定（`end_when`） | 配る前・準備中に誤って出ない |
| 9 | 非厳格モード | 外れた行為（役職のない人の能力）で情報を得られない → 作品は `game.strict: true` |
| 10 | 画面（`bg serve`、見る立場を Pn に） | 1〜6 と同じものが画面にも出ない |

## 手順

1. 作品の隠れた情報を一覧にする（誰が・何を・いつまで知らないか）。
2. 小さな対局を作り（`bg new … --seed`）、隠れた情報が動く場面まで進める（キーパーで行ってよい）。
3. 表の 1〜10 を、見てはいけない人の立場で実行して確かめる。漏れは、実行したコマンドと出力の該当行を控える。
4. 漏れを直す：定義で直せるもの（`secret`・`whisper`・`strict`・条件の書き方）は定義で、出力の作りの問題はエンジンで。直したら、その漏れを再現するテストを足す（`tests/test_social.py` の人狼のテストが手本）。
5. 報告：隠れた情報の一覧、表の結果（○・×）、直したもの、受け入れた制限（例：`--by` の名乗りは信じる、notes/loop L16）。
