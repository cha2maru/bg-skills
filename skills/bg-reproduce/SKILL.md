# bg-reproduce：既存の作品 → 生成スクリプト → 定義

> **どこで使っても**：`bg` はプラグインが PATH に入れるコマンド（このリポジトリの中なら `uv run bg`）。コマンドの一覧は `<プラグインのルート>/docs/commands.md`。形式の当てはめは `<プラグインのルート>/skills/bg-design/SKILL.md` の手順 2。市販品の再現の実例は、このリポジトリでは `local/`（git 管理外）にある。

## 手順

1. **権利と使い道を確かめる**
   - 使い道：個人の検証・非営利に限るか。作品の二次創作ガイドライン・コモンズ（素材集）の条件を読む。
   - 表記：出典（作品名・作者・版元）と、素材を使うなら条件どおりの表記とリンク。生成スクリプトの冒頭の文と、定義の `game.sources` に書く。
   - 置き場：定義・資料・生成スクリプト・思考ルーチンはすべて `local/`（git 管理外）。公開しない（RUL-001 #37）。画像は条件が許すときだけ使う。地図などの素材の利用条件（GPL など）も書く。
2. **資料を集める**（`local/<名前>/` に置く。手で写さない）
   - 遊ぶ人向けの公開ルール。手引きの文（R1…）の元にする。
   - 詳細ルール・総合ルール・審判用の決まり（テキストにして置く）。
   - 元のエンジンがあれば、その局面の写し（ブラウザで開き、初期の局面を JSON に取り出す。取り出すスクリプトも `local/<名前>/` に残す）。カード・数値は写しから取る。
   - ボードの画像・地図の SVG（領域の形を取り出す元）。
3. **生成スクリプトを書く**：`local/gen_<名前>.py` が `local/<名前>.yaml` を書き出す。
   - データは資料から読む（写しの JSON、ルールの節、SVG のパス）。手で打つのは資料に無い対応づけだけ。
   - 何度でも作り直せること（`uv run python local/gen_<名前>.py`）。出力の 1 行目に `# 生成：local/gen_<名前>.py（直接編集しない）`。直すのはスクリプト。
   - 冒頭の文に、出典・資料の版・再現の範囲（入れたもの・文だけで持つもの）を書く。範囲を推奨で決めたら「推奨で決めた（RUL-018）」と書く。
   - 読み取れたはずの値は `assert` で確かめる（形が見つからない州、写しに無いカード）。
4. **形式に当てはめる**（bg-design の手順 2 の原型の表。形式を足さない。RUL-016）
   - 詳細ルールは節ごとに `rules` へ `detail: true`、`source` に節番号と版。手引きの文はその要約。アクションの `rule` は実装した節を指す。
   - ボードの絵・地図は、親に `viewbox`（画像なら `image`）、子に `path`・`xy`。見栄えの場所は `slot: true`。
   - 元の呼び名を `terms` にそろえる。避ける言い方は `avoid`、初出の表記は `first`（例：`波（ウェーブ）`）。
5. **穴を裁定にする**（`rulings`。RUL-017）：資料で決まらない点、骨組みに入れなかった点を 1 件ずつ。
   - 決められないもの：`status: open`、`question`・`rules`・`date`。
   - 決めたもの：`decision`・`reason`・`authority`（自分で決めたなら `keeper`）・`sources`。推奨で決めたら理由に「推奨で決めた（RUL-018）」。
   - 一次資料で明文が見つかったら、裁定を直して `sources` に書く。
6. **確かめる**（すべて通るまで、生成スクリプトを直して作り直す）
   ```bash
   uv run python local/gen_<名前>.py
   bg check local/<名前>.yaml
   bg fuzz local/<名前>.yaml --players N --steps 150
   bg selfplay local/<名前>.yaml --players N --games 30
   ```
   - 元の作品にコンピューター役があれば、bg-ai で思考ルーチンにする（考える順番に元の作品の出典を書く。`local/<名前>/bots/`）。`bg league` で random に勝てるか。
7. **報告**：定義と生成スクリプトの場所、資料と版、出典とコモンズの表記（そのまま貼れる文）、再現の範囲（文だけで持つもの）、未決の裁定の一覧、`bg fuzz`・`bg selfplay` の結果。次は bg-playtest か bg-rules-audit。

## やらないこと

- `local/` の外に置くこと、コミットすること、公開すること。
- 生成された YAML を手で直すこと。
- 資料に無いルールを決めて書くこと（裁定に `status: open` で残す）。
- 形式・エンジンを直すこと。書けない点は、どこが書けないかを報告する（RUL-005・RUL-016）。
