# bg-ai：ルールに則した思考ルーチンを作る

> **どこで使っても**：`bg` はプラグインが PATH に入れるコマンド（このリポジトリの中なら `uv run bg`）。コマンドの一覧は `<プラグインのルート>/docs/commands.md`（プラグインのルートは、このスキルのディレクトリから 2 つ上）。手本は `<プラグインのルート>/examples/bots/`（harvest-greedy.md と .py）。考え方の元は先行プロジェクト sangeki（惨劇RoopeR の脚本家・主人公の思考ルーチン）の流れ（RUL-030）。

## 考え方（sangeki で分かったこと）

1. **処理と判断を分ける。** ルールの処理はエンジン（定義）、判断は差し替えられる思考ルーチン。思考ルーチンは `choose(ctx)` で、`ctx.moves`（今行える手）から 1 つを返すだけ。ルールを思考ルーチンの中で処理し直さない。
2. **見える物だけで考える。** `ctx.view`（その席の見え方）、`ctx.part(id)`（見えている部品の定義）、`ctx.log`（その席に見える記録）だけを使う。見えない手札・山札の中身を `ctx.part` で引こうとすると KeyError になる。ただし、これは**決まり（約束）で、仕組みで止めてはいない**。思考ルーチンは同じ Python のプロセスの中で動くので、ctx の外（`ctx._s`、対局の log.jsonl）にも手が届く。読まないのは書く人の約束。隠れた情報は、公開された出来事から推理する。
3. **でたらめを土台にする。** まず `--bot random` どうしで終わりまで回ることを確かめる。思考ルーチンは、でたらめに勝てるかから測る。
4. **ルールから「考える順番」を作る。** 勝ち筋・負け筋と、その残り（あと何点・あと何 HP・あと何手番）を、ルールの文と機械の層から数える。
5. **段で比べる（足し合わせない）。** 「今取れる勝ち ＞ 必ず取れる手 ＞ 見込みの高い手 ＞ 隠す・備える」のように、上の段が決まれば下は見ない。点数を足し合わせると、隠すための加点が勝てる手を押しのける（sangeki で、取れたはずのループをこれで落とした）。
6. **同点はくじ。** 毎回同じ手にすると読まれる。`ctx.rnd` で選ぶ。
7. **勝率だけで測らない。** 局の長さ、得点の内訳、決着しない割合、作品の目標（最後の戦いに届いた割合など）も見る。コンピューターどうしの数字は甘く出る。採用は、人か Claude が目隠しで対戦して確かめてから（手順 6）。
8. **人が読める手順として書く。** 思考ルーチンは、まず `bots/<名前>.md` に「考える順番」（表。各行に根拠のルール）として書き、それをそのまま `bots/<名前>.py` にする。入っていない判断（苦手なこと）も書く。

## 手順

1. **土台**：`bg league <定義> --bot a=random --bot b=random --players N --games 5` が終わりまで回り、断られた手（refused_moves）が 0 か。回らなければ定義の不具合（同じ行為を無限に繰り返せる、など）として bg-design・bg-rules-audit で直す。
2. **考える順番を書く**（`bots/<名前>.md`）：手番の場面ごと（例：手番の初め・戦闘・村・割り込み）に、上から見る問いの表。根拠のルール ID、見ているもの（見え方のどこか）、苦手なこと。既存の作品にパソコン役の思考ルーチンがあれば、その考え方を写して出典を書く。
3. **コードにする**（`bots/<名前>.py`）：`choose(ctx)` を書く。使えるもの：
   - `ctx.moves`：今行える手（`{"action", "args"}`、`{"advance": "phase"|"turn"}`、`{"pass": True}`）
   - `ctx.find(action, **args)`：手を絞る。`ctx.area(id)`・`ctx.count(id, kind)`：見え方の置き場。`ctx.part(id)`：見えている部品の種類と属性
   - `ctx.view`：見え方そのもの（組の記録の状態など）。`ctx.player`、`ctx.rnd`
   - `ctx.log`：記録を、その席に見える形で（`bg log --as` と同じく伏せる。相手が伏せて捨てた札・内緒の行為は出ない）。相手が何を出したか、何枚引いたかなど、公開された出来事からの推理に使う。読んだときに 1 回だけ作るので、読まなければ遅くならない
   - 戻り値は手か、`(手, "理由")`、`(手, "理由", 差)`。差は 1 番目の手と 2 番目の手の点数の差（段で比べるなら、段ごとに重みを付けて 1 つの数にする。手本の harvest-greedy.py）。理由は `note`、差は `margin` として `--trace` の記録に残る
4. **測る**：`bg league <定義> --bot 新=bots/新.py --bot random --players N --games 20 --record experiments.jsonl --note "..." --trace trace.jsonl`。方針を席に回すので、席の有利は打ち消される。方針が 2 つなら、同じ種の対局どうしの符号検定（`paired.sign_test_p`）も出る。
5. **読む**：`trace.jsonl` で、理由の付いた判断を追う。同じ行為の繰り返し、狙いが途中で変わる、金・資源をため込む、などの癖を探す。それぞれ、思考ルーチンの直しか、定義の直し（ルールの穴）かを分ける。
   - **迷った局面**：`margin` の小さい行（0 は同点をくじで決めた手）を小さい順に拾う（`grep '"margin": 0[,}]' trace.jsonl` でくじの手）。考える順番の表がその手どうしを分けていない局面なので、表に行を足すか、目隠しの対戦（手順 6）で人がどちらを選ぶかを見て決める。
6. **目隠しで対戦する**（`bg bot-step`）：1 席を人か Claude が指し、ほかの席を思考ルーチンが指す。
   - 対局を作る：`bg new sessions/vs1 --def game.yaml --players 2 --seed 1`
   - ほかの席を進める：`bg bot-step sessions/vs1 --human P1 --bot P2=bots/新.py`。人の席の番が来た（`stopped: human`。`human:` にその席）、終わった（`ended`）、だれも動けない（`stuck`。定義の不具合として bg-rules-audit へ）、`--max` 手を足した（`max`。もう一度行う）のどれかで止まる。`--bot` を書かない席はでたらめ。キーパーの準備・進行も進める。手は通常の記録（log.jsonl）に足すので、画面にもそのまま出る。人の席が 2 つなら `--human` を 2 回書く。人の席が 1 つなら、足した手を `moves`（その席に見える形）で出し、終わったら `result`（勝ち負けと順位）も出す。画面などが同時に書いたら、その手は記録せず読み直して選び直す
   - **Claude が指す**：サブエージェントに 1 席を渡す（渡し方は bg-playtest）。手番ごとに `bg show sessions/vs1 --as P1 --compact` と `bg candidates sessions/vs1 <アクション> --by P1` で見て、`bg act sessions/vs1 <アクション> --by P1 --arg card=...` で指す。`bg show` の `flow.available` に行えるアクションが残っていなければ（手番の回数を使い切ったら）、`bg advance sessions/vs1 --to turn --by P1` で手番を終える（終えないと bot-step は `stopped: human` のまま何もしない）。それから `bg bot-step`（同じ引数）で相手の番を進める。相手の手は bot-step の `moves` で読む（前の手までさかのぼるなら `bg log sessions/vs1 --as P1`）。自分の手で終わることもあるので、`bg act` が「対局は終了している」と断ったら、`bg show --as P1` の `result` を見る。log.jsonl と、`--as` を付けない bg show は読まない
   - **人が指す**：`bg serve sessions/vs1 --host 127.0.0.1` で画面を開き、「見る立場」を自分の席にする（認証が無いので外に公開しない）。自分の手番を終えたら、端末で `bg bot-step`（同じ引数）を行う。画面は 1.5 秒ごとに記録を読み直す
   - 手番のない段階（準備・夜）では、思考ルーチンの席が先に済ませ、人の席にまだ行っていない段階のアクションがあれば human で止まる。行わないなら `bg advance sessions/vs1 --to stage`
   - 見るもの：思考ルーチンが崩れる局面（明らかに悪い手・同じ手の繰り返し）、人が勝てた筋、手順 5 の迷った局面で人が選んだ手。勝つ筋が 1 つに決まってしまうなら、思考ルーチンの直しか、定義の直し（ルールの穴）かを分ける
7. **改良する**：名前つきの版（`bots/新2.py`）を作り、前の版と `--bot 新=... --bot 新2=...` で比べる。採るのは、リーグ戦で前より良く（p が小さく）、目隠しの対戦（手順 6）でも崩れないものだけ。判断は `journal.md` に、根拠の試行と一緒に書く。
8. **バランスに使う**：良い思考ルーチンどうしのリーグ戦で、案（`--with`）ごとの席の有利・長さを比べる（bg-balance）。でたらめの対戦より、作品の実際に近い数字になる。

## 報告

思考ルーチンの考える順番（表）、リーグ戦の結果（勝ちの割合と 95% の幅 `win_ci`・平均の順位・席ごと・符号検定）、記録から見つけた癖と直したもの、迷った局面、目隠しの対戦の結果（勝ち負けと崩れた局面）、苦手なこと、次に試すこと。

## 注意

- 思考ルーチンに局面そのもの（隠れた情報）を渡さない。必要なら、公開の出来事からの推理を思考ルーチンの中に書く。
- 思考ルーチンに入れたい判断（例：成長の報酬を選ぶ、組ごとの目標を進める）に、定義の行為や状態が無ければ、先に定義に機械の層を足す（bg-design・bg-rules-audit）。文だけのルールは、思考ルーチンからは見えない。確かめられない細部は裁定（`status: open`）に残す。
- 1 局が遅いときは、合法手の数（引数の組み合わせ）が多すぎないかを見る（`--trace` の n_moves）。
- 市販品の作品の思考ルーチンは、定義と同じく local/ に置く。
