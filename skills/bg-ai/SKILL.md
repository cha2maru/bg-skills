# bg-ai：ルールに則した思考ルーチンを作る

> **どこで使っても**：`bg` はプラグインが PATH に入れるコマンド（このリポジトリの中なら `uv run bg`）。手本は `<プラグインのルート>/examples/bots/`（harvest-greedy.md と .py）。考え方の元は先行プロジェクト sangeki（惨劇RoopeR の脚本家・主人公の思考ルーチン）の流れ（RUL-030）。

## 考え方（sangeki で分かったこと）

1. **処理と判断を分ける。** ルールの処理はエンジン（定義）、判断は差し替えられる思考ルーチン。思考ルーチンは `choose(ctx)` で、`ctx.moves`（今行える手）から 1 つを返すだけ。ルールを思考ルーチンの中で処理し直さない。
2. **見える物だけで考える。** `ctx.view`（その席の見え方）と `ctx.part(id)`（見えている部品の定義）だけを使う。見えない手札・山札の中身は引けない（引こうとすると KeyError）。隠れた情報は、公開された出来事から推理する。
3. **でたらめを土台にする。** まず `--bot random` どうしで終わりまで回ることを確かめる。思考ルーチンは、でたらめに勝てるかから測る。
4. **ルールから「考える順番」を作る。** 勝ち筋・負け筋と、その残り（あと何点・あと何 HP・あと何手番）を、ルールの文と機械の層から数える。
5. **段で比べる（足し合わせない）。** 「今取れる勝ち ＞ 必ず取れる手 ＞ 見込みの高い手 ＞ 隠す・備える」のように、上の段が決まれば下は見ない。点数を足し合わせると、隠すための加点が勝てる手を押しのける（sangeki で、取れたはずのループをこれで落とした）。
6. **同点はくじ。** 毎回同じ手にすると読まれる。`ctx.rnd` で選ぶ。
7. **勝率だけで測らない。** 局の長さ、得点の内訳、決着しない割合、作品の目標（最後の戦いに届いた割合など）も見る。コンピューターどうしの数字は甘く出る。採用は、人か Claude が目隠しで対戦して確かめてから。
8. **人が読める手順として書く。** 思考ルーチンは、まず `bots/<名前>.md` に「考える順番」（表。各行に根拠のルール）として書き、それをそのまま `bots/<名前>.py` にする。入っていない判断（苦手なこと）も書く。

## 手順

1. **土台**：`bg league <定義> --bot a=random --bot b=random --players N --games 5` が終わりまで回り、断られた手（refused_moves）が 0 か。回らなければ定義の不具合（同じ行為を無限に繰り返せる、など）として bg-design・bg-rules-audit で直す。
2. **考える順番を書く**（`bots/<名前>.md`）：手番の場面ごと（例：手番の初め・戦闘・村・割り込み）に、上から見る問いの表。根拠のルール ID、見ているもの（見え方のどこか）、苦手なこと。既存の作品にパソコン役の思考ルーチンがあれば、その考え方を写して出典を書く。
3. **コードにする**（`bots/<名前>.py`）：`choose(ctx)` を書く。使えるもの：
   - `ctx.moves`：今行える手（`{"action", "args"}`、`{"advance": "phase"|"turn"}`、`{"pass": True}`）
   - `ctx.find(action, **args)`：手を絞る。`ctx.area(id)`・`ctx.count(id, kind)`：見え方の置き場。`ctx.part(id)`：見えている部品の種類と属性
   - `ctx.view`：見え方そのもの（組の記録の状態など）。`ctx.player`、`ctx.rnd`
   - 戻り値は手か、`(手, "理由")`（理由は `--trace` の記録に残る）
4. **測る**：`bg league <定義> --bot 新=bots/新.py --bot random --players N --games 20 --record experiments.jsonl --note "..." --trace trace.jsonl`。方針を席に回すので、席の有利は打ち消される。方針が 2 つなら、同じ種の対局どうしの符号検定（`paired.sign_test_p`）も出る。
5. **読む**：`trace.jsonl` で、理由の付いた判断を追う。同じ行為の繰り返し、狙いが途中で変わる、金・資源をため込む、などの癖を探す。それぞれ、思考ルーチンの直しか、定義の直し（ルールの穴）かを分ける。
6. **改良する**：名前つきの版（`bots/新2.py`）を作り、前の版と `--bot 新=... --bot 新2=...` で比べる。採るのは、リーグ戦で前より良く（p が小さく）、目隠しの対戦（人か Claude が席の見え方だけで遊ぶ。bg-playtest）でも崩れないものだけ。判断は `journal.md` に、根拠の試行と一緒に書く。
7. **バランスに使う**：良い思考ルーチンどうしのリーグ戦で、案（`--with`）ごとの席の有利・長さを比べる（bg-balance）。でたらめの対戦より、作品の実際に近い数字になる。

## 報告

思考ルーチンの考える順番（表）、リーグ戦の結果（勝ちの割合・平均の順位・席ごと・符号検定）、記録から見つけた癖と直したもの、苦手なこと、次に試すこと。

## 注意

- 思考ルーチンに局面そのもの（隠れた情報）を渡さない。必要なら、公開の出来事からの推理を思考ルーチンの中に書く。
- 1 局が遅いときは、合法手の数（引数の組み合わせ）が多すぎないかを見る（`--trace` の n_moves）。
- 市販品の作品の思考ルーチンは、定義と同じく local/ に置く。
