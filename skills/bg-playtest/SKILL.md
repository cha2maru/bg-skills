# bg-playtest：エージェントによる試し遊び

> **どこで使っても**：`bg` はプラグインが PATH に入れるコマンド（入れていない、このリポジトリの中なら `uv run bg`）。下の `examples/`・`specs/`・`src/`・`tests/`・`CLAUDE.md` は**プラグインのルート**（このスキルのディレクトリから 2 つ上）の中のファイル。コマンドの一覧は `<プラグインのルート>/CLAUDE.md` の「コマンド」の節。作る定義・対局は、利用者のプロジェクトに置く。

テストにない使い方の詰まりや情報の漏れは、エージェントに実際に遊ばせると見つかる（精霊獣デュエル・カタン・人狼で、それぞれ重要な不具合が見つかった。notes/loop の 8・13・19 回）。

## 手順

1. **何を見るかを決める**：作品の特徴から、試す場面を 4〜6 個に絞る。
   - カードの効果：効果の解決、状態異常、きぜつ、手番の初めの処理
   - 交渉：成立・断る・条件を変えて返す・果たせない提案・内緒の提案・銀行
   - 隠れた情報：内緒話・夜の行動・封をした投票・占い・取り消し
   - 割り込み：積む・応じる・見送る・打ち消す・立ち消え
2. **サブエージェントに頼む**（バックグラウンド。Agent ツール、general-purpose）。頼む文に必ず入れること：
   - `<プラグインのルート>/CLAUDE.md` のコマンドの節を先に読む（パスを書いて渡す）。使うのは `bg` コマンドだけ（`bg show --as Pn --compact`、`--only`、`bg candidates`、`bg act`、`bg say`、`bg pass`、`bg advance`）。
   - 全員の席を正直に遊ぶ：Pn として判断するときは `bg show --as Pn` だけを見る。
   - 対局のフォルダはスクラッチパッドの中。リポジトリのファイルは直さない・コミットしない。
   - 1 局（か N 手番）遊び切る。試す場面の一覧。
   - 報告：結果、問題の一覧（重い順。実行したコマンド・期待・実際・エラー文）、それぞれの最小の直し方、手番あたりのコマンド数、確かめていないこと。
   - 隠れた情報のある作品では、bg-hidden-info-audit のチェック表を渡し、漏れを探させる。
3. **ルールの穴は裁定にする**：試し遊びで問いになった点（文で決まらなかった点）は、定義の `rulings` に書く（決まらなければ `status: open`）。キーパーが対局中に裁いたものは `bg rulings <対局>` で持ち帰る。
4. **報告を受けて直す**：重い順に、エンジンの不具合（`src/bgskills`）と定義の不具合を分ける。直したらテストを足し（`tests/`）、`uv run pytest -q` と画面のテストを通す。判断は `specs/versions/v2/okf/notes/*/gates.md` に 1 行ずつ。直さないもの（受け入れる制限）も理由と書く。エンジンを直すのは bg-skills のリポジトリの中だけ。ほかのプロジェクト（プラグインとして使うとき）では、定義だけを直し、エンジンの不具合は報告にとどめる（プラグインのフォルダは直さない）。
5. **報告**：遊んだ結果、見つかった点と直したもの・残したもの。

## 注意

- サブエージェントの報告は、そのまま信じず、再現してから直す（例：古い対局は定義の変更で再生できなくなっていることがある → `bg rebase`）。
- 市販品の定義（`local/`）を遊ばせるときは、報告に定義の中身を長く写さないよう頼む。
