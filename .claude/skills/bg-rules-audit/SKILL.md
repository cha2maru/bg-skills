# bg-rules-audit：ルールと定義の突き合わせ

ルールの中身は自然文が正本（RUL-001 #31）。定義はその一部を機械で確かめられる形にしたもの。両者のずれと、ルールそのものの穴を探す。

## 手順

1. **機械で確かめる**
   - `uv run bg check <定義>`：参照・式・名前の打ち間違い
   - `uv run bg fuzz <定義> --players N`：一度も行えないアクション（`never_done`）、式の誤り
   - `uv run bg stats <対局…>`：使われなかったルール
   - `uv run bg complexity <定義>`：ルールの数・条件・式の大きさ・どのアクションにも終わりの条件にも結びつかないルール（`rules_text_only`）
2. **ルールごとに突き合わせる**（`rules` の 1 件ずつ）
   - そのルールを行うアクションがあるか（アクションの `rule`）。ないなら、自然文だけで扱う理由があるか（解釈・裁定）。
   - アクションの条件（`require`・`when`・進行の区分と回数）が、ルールの文と同じか。文にない条件、条件にない文はないか。
   - 例外（「ただし」「〜のときは」）が条件か自然文のどちらかにあるか。
   - 終わりと勝敗（`end_when`）がルールの文と同じか。同時に満たしたときの扱い（引き分け・優先）は書いてあるか。
3. **ルールの穴を探す**：同数・同時・山札切れ・置き場の上限・誰も行えない局面・手番を飛ばす・棄権。見つけたら定義の `rulings` に書く（決められれば `decision` と `reason`・`authority`、決められなければ `status: open` で問いだけ）。`bg rulings <対局>` で、対局中の裁定から持ち帰る候補も見る。書き方は examples/rune-clash.yaml の rulings と、sangeki の wiki/notes/rulings.md を手本にする。
4. **報告**：表（ルール ID・対応するアクション・ずれ・直し方）、穴の一覧と案、直したもの。定義を直したら `bg check`・`bg fuzz` を通し直す。
