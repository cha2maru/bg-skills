# bg-balance：測って、1 つ変えて、比べる

## 手順

1. **何を測るかを決める**：先手・後手の勝率、デッキ（陣営）ごとの勝率、局の長さ（手番数）、使われないアクション・ルール（`bg stats` の未使用）、特定のカードの勝ちへの寄与。
2. **局を集める**
   - まず `uv run bg selfplay <定義> --players N --games 30` で目安を取る（作品を問わない。今行える手からでたらめに選ぶので弱いが、終わり方の偏り・局の長さ・進められない局面が分かる）。
   - ボットがある作品はボットで（例：`uv run python local/duel-bot.py 50`）。ボットは定義のアクションと `bg candidates` だけで手を選ぶ（作品専用のルール処理を持たない）。ボットがなければ、`bg candidates` の条件を満たす候補から選ぶ簡単なボットを scratchpad に書く。
   - 偶然を分けるため、種（`--seed`）を変えて最低 30 局。席は交互に。
   - `uv run bg stats <対局…>` で席ごとの勝敗・未使用のルール・操作数を集める。
3. **差が偶然でないか**：勝率の 95% の幅（およそ ±1.96×√(p(1−p)/n)）を添える。幅が 50% をまたぐなら「偏りは見えない」と報告する。
4. **1 つだけ変える**：定義の数値（HP、ダメージ、コスト、枚数、サイドの枚数など）を 1 か所変え、`game.version` を上げるか別名で保存し、同じ種の組で測り直す。進行中の対局を続けて使うなら `bg rebase`。
5. **報告**：表（変えた所・局数・勝率と幅・局の長さ）、推奨の変更 1 つと理由、測っていないこと（ボットの弱さ・偏った戦略など）。ルールの文も直す必要があれば bg-rules-audit で確かめる。

## 注意

- ボットの強さの偏りは、ゲームの偏りと区別できない。可能なら 2 種のボット（ランダム寄り・欲張り）で同じ傾向か確かめる。
- 数値を同時に 2 つ以上変えない。
