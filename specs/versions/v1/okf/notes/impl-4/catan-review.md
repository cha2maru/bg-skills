# レビュー：カタンの仕上げと 2 回目のエージェントの対局（2026-11-19）

| G1 選択式・G2 値と式 | expr.py（決まった関数だけの式。内包表記可） | 産出の対象、港の配置、初期配置の資源 |

## 2 回目の対局（サブエージェント。補助スクリプトなし）

準備・初期配置（往復・候補で距離の決まり）・本番 18 手番（7 が 3 回、発展カード、建設、交換 6 回）。bg 約 210 回（1 手番 5〜8 回）。前回の不満：リンク（ほぼ解消）、検査（解消）、段階の切り替え（一部）、出力の大きさ（一部）、結果（解消）、記録の見え方（ほぼ）、産出（解消）。

## 指摘と対応（SPC-055）

| 指摘 | 対応 |
|---|---|
| 奪った資源の種類が第三者の記録に見える | 区別しない部品の操作も、移る元・先の表面が見えなければ伏せる |
| 最長の街道が分かれ道で多く数える | 入ってきた端とは別の端から先へ（Y 字で 2） |
| 港が辺の空きを埋める | 種類の fixture（場所の性質）を空き・上限に数えない |
| フェーズの切り替えが手作業 | フェイズの auto（ダイス・初期配置）、結果に移った後の進行 |
| 区別しないコマの ID 指定 | 引数の pick: first |
| 候補が費用を見ない | アクションの require（費用）を候補の action_problems に |
| 定義の不足（初期の街道の候補、街道建設のつながり、資源の枚数、捨てる枚数） | catan.yaml を直した |

## 残り

- フェーズの終わりを「回数で終わる」と「宣言で終わる」で区別する（今は auto と手動の advance）
- 操作の結果を当事者にだけ見せる一般の仕組み（今は記録の伏せで代用）
- 最小の表示（自分の手札・出目・得点・できることだけ）
- 称号の判定の例（局面と期待値）を定義に持つ（指標のテストの例）
- 終了の検出・独占・収穫・港の交換は、エージェントが試していない（テストでは確かめた）
