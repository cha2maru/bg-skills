# レビュー：惨劇RoopeR の再現とエージェントの対局（2026-11-19）

定義：local/tragedy-looper.yaml（公開してよい部分：盤・キャラクター・行動カード・惨劇セットの役職・ルール・事件の一覧・進行）と、local/tragedy-looper-scenario-s01.yaml（脚本：配役・使うルール・犯人。非公開）。根拠は sangeki のデータと wiki。どちらも公開しない（RUL-001 #37）。

## エージェントの対局（サブエージェント。補助スクリプトなし）

2 ループを通した：1 ループ目は主人公の勝ち（神社に暗躍禁止、犯人候補に不安−1）、2 ループ目は脚本家の勝ち（因果の糸・不安禁止・移動の合成で封印が成立。ウイルスのシリアルキラーが 3 人を殺害）。3 ループ目の初めまで。430 操作、bg 約 300 回（1 日約 20 回）。局面と記録からの見え方の漏れはなかった。

## 指摘と対応（SPC-056）

| 指摘 | 対応（汎用の概念） |
|---|---|
| 定義ファイルに配役・犯人が平文（主人公役が読める） | **シナリオ**：対局ごとの非公開の設定を定義から分け、対局のフォルダに写す（--scenario） |
| ルール違反が警告だけで通る（警告を見落とした） | **厳格モード**（対局ごとに選ぶ。既定は警告） |
| 主人公行動の順番・1 人 1 枚が強制されない | フェーズの **per_player**（1 人あたり）と **sequence: from_active**（手番のプレイヤーから順に） |
| 行動解決が 1 日の作業の半分以上 | 式・繰り返し・分岐で書いた **解決表**（resolve-cards。打ち消し・移動の合成・禁止エリア）。エンジンに作品の決まりを入れずに、定義だけで書けた |
| advance を 1 日 8 回、数え間違い | **pass**（行うことのないフェーズを通り過ぎる）、**auto**（回数で次へ）、advance の **until** |
| 因果の糸：前のループの友好を覚える | **記憶**：progress に式の値を書き残す（loop-end） |
| ループの勝敗が記録に残らない | loop-end が勝敗を進行の状態に積む |
| ウイルスの役職の変化・シリアルキラーの対象が見えない | **値つきの知らせ**（{value}）：キーパーにだけ一覧で示す |
| signals と end_signals の見出し | 分けた |
| 神社の暗躍の指標がルール Y をほのめかす | 指標の **visible: keeper** |
| 主人公の画面に脚本家のアクションが並ぶ | アクションの **by**（行える人） |
| ボードに置く条件の誤り（キャラクターの上の札まで数える） | 直接置かれた物の **on()**。parts_in・count_in は子のエリアも含めるよう直した |
| candidates に先に決めた引数を渡せない | --arg |
| show の出力の絞り込み | --only |

## まだ再現できないもの（手で行う）

| もの | 必要な概念（案） |
|---|---|
| 役職の能力（クロマク・ミスリーダー・キラーなど）、キャラクターの友好能力の効果 | 能力の宣言と効果を、アクション（条件・式の手順）として書く。今の仕組みで書けるが、まだ書いていない（定義の作業） |
| 友好能力の使用条件（神社にいないと使えない など） | 能力ごとの条件の式（今の仕組みで書ける。データに条件の構造がない） |
| 事件の効果（不安拡大・邪気の汚染・自殺・殺人事件・病院の事件…） | 事件ごとのアクション（今の仕組みで書ける） |
| 最後の戦い | 遊んでいない。役職の宣言と正誤の判定は、脚本と比べる式で書ける |
| 「事件は起きなかった」を記録に残す | 何もしないアクション（note）として書ける |

結論：作品の決まりは、エンジンに入れずに定義（式・繰り返し・分岐・条件・記憶・知らせ）だけで書ける見込みが立った。残りは定義の作業量。
