# 詳細ルール（審判用の総合ルール）の整理（RUL-024）

題材：『新幕 桜降る代に決闘を』総合ルール（BakaFire Party。2025/06/02 版。86 ページ。コアルール §1〜§10・追加ルール（メガミごと）・附則（メガミリスト・エラッタ））。
大会で「より厳格に運用する」ための文書で、遊ぶ人の手引き（ルールブック）より細かい。

## 判断

| # | 問い | 決めたこと | 理由 |
|---|---|---|---|
| D1 | 詳細ルールを定義のどこに置くか | `rules` の 1 件ごとに `detail: true`（CTR-F-001 r4）。裁定（rulings）には入れない | 総合ルールは「文で決まらない穴への答え」ではなく、作者が出した正本の文。問い・裁定の形にならない。rules に印なしで入れると、手引きが 86 ページ分に膨らむ |
| D2 | 手引きに出さないとは、どこに出さないか | 画面のルール欄（手引きの後に「詳細ルール」としてたたむ）、TTS の書き出し（出さない）。定義・見え方の意味・`bg complexity`（rules_detail）・裁定の根拠には出す | 利用者の指定「ユーザマニュアルには出さないが、定義としては必要」 |
| D3 | 強さ | 詳細ルール＞手引きのルール＞裁定＞機械の層 | 手引きは詳細ルールの要約。食い違えば詳細ルールが正しい（総合ルールの目的が厳格な運用） |
| D4 | 機械の層はどちらを指すか | アクションの `rule` は詳細ルールの節（例：CR9-6 基本動作）。手引きのルールは refs で詳細ルールを指し、`bg complexity` はそれを通じて機械の層を持つと数える（via） | 機械の層が実装しているのは細かい方の文 |
| D5 | 詳細ルールの文の持ち方 | 節をそのまま取り込む（`source` に節番号と版）。言い換えない | 正本なので。二次創作ガイドライン「文書の転載は出典を明記すれば禁止しない」。市販品なので local/ に置き公開しない |

## 形式で書けなかったこと（項目は足していない。次の候補）

| 書けなかったこと | 今の扱い | 候補 |
|---|---|---|
| 効果が《攻撃》を生成する（圧気の【破棄時】） | 文だけ | 「攻撃」を部品（トークン）として生成する手順。stack の引数で代わりになるか試す |
| 状況起因（条件を満たしたら直ちに解決する効果）の一般形 | 起きうる場所ごとに手順で書いた | flow の監視（signals を手順つきに）。足すなら CTR-F-001 の版を上げる |
| 「このターンに次に行う《攻撃》は〜」（後の行為への修正の予約） | 文だけ（柄打ち・体捌き・バックドラフト） | 決闘者の札の状態に予約を書き、式で読む（形式は今のままで書ける見込み） |
| 受ける人の選択を手順の途中で聞く（焦燥のオーラ・ライフ） | オーラで受けられればオーラ（J3 は未決） | アクションを 2 つに分ける |
| 双掌繚乱（メガミの選択）とカードの使用者 | 省略（両者ユリナ・ヒミカ） | 候補のカードをメガミで分ける置き場 |

## 再現で見つかったエンジンの不具合（直した）

- 引数を読むアクションの条件で、見え方（行えない理由の一覧）の計算が失敗した → 選ぶまで判断できない条件は理由に出さない（query.check_action）。
- 画面が、見え方を作れなかったとき前の立場（キーパー）の局面を出し続けた（漏れ） → 局面を消して知らせる。
- `bg candidates`・`/api/candidates` が、置き場を書かない引数で、相手の見えない部品の ID を出した（漏れ） → redact.visible_candidates で伏せる。tests/test_leaks.py に足した。
- でたらめのボットが、今のフェイズで行えることがないと手番ごと飛ばした（メインフェイズに入らない） → 先にフェイズを進める。
