# 概念定義の再レビュー（2026-11-19）

材料：RUL-001〜003 の発言、第一弾〜第三弾の実装（src/bgskills）、例の定義（三目並べ・かがり火・六角の陣取り）、カタンの再現（local/catan.yaml）、エージェント（サブエージェント）がカタンを bg コマンドだけで遊んだ報告。

## 1. 今の概念モデル

### 定義の層（対局の前に決まっている）

| 概念 | 定義 | 実装での形 | 根拠 |
|---|---|---|---|
| ゲーム定義 | 1 つのゲームの 1 つの版の、対局前に決まっている情報のすべて | YAML（bg-def/0.1） | RUL-001 #25・#33 |
| プレイヤー（席） | 判断し勝敗の主体になる立場。席につく者（人・エージェント・オートマ）とは分ける | players、対局の seats | #7・G8 |
| 種類 | エリアかオブジェクトの型。元の種類を継承する | kinds（base） | #10 |
| 部品 | 箱の中の 1 個 1 個。属性・持ち主・初期の置き場。区別しないものは個数 | objects（copies・count・owner） | G2・G14 |
| エリア | 部品やほかのエリアを置ける場所。入れ子・位置・リンク・形状・公開範囲・順番・上限・入ったときの状態 | areas（areas・pos・xy・visibility・ordered・capacity・on_enter） | #9・#11・#13・#16・#17・RUL-003 #2 |
| 箱 | 卓の外のエリア。どの定義にもある | box | RUL-002 #23 |
| 状態 | 部品が局面ごとに取る値。値ごとに意味（text）と表示方法（show：回転・表裏） | kinds.states | #18・RUL-002 #18 |
| 属性 | 対局の中で変わらない値 | attributes | #19 |
| リンク | 2 つのエリアの関係（種類つき）。六角の盤では自動で作る | links、layout.hex | #16・RUL-003 #1 |
| 組 | 名前のついたエリアの集まり | groups | 方針再検討 |
| 卓の配置 | 中央と席ごとのエリア | table | RUL-002 #12 |
| ルール | 自然文が正本。区分・参照・出典 | rules | #7・#31 |
| 用語 | ルール文の中の特別な言葉 | terms | 方針再検討 |
| アクション | ルールに結びついた、名前つきの操作の手順。引数（選ぶもの）と条件を持つ | actions（params・require・steps） | RUL-002 #19・#20 |
| 条件 | 引数が満たすべき、構造だけで決まる述語（空き・中身・リンクのつながり・否定・いずれか・すべて） | params.require | RUL-003 #7（本レビュー） |
| 指標 | 局面から数えて出す値（使った騎士・都市の数・勝利点） | metrics（count・sum・visible） | RUL-003 #5 |
| 進行の構造 | 段階・手番・フェーズ、アクションの区分（メイン・フリー・手番外）と回数、手番の順 | flow | RUL-003 #6 |
| 進行の状態 | ゲーム固有の、部品に属さない変わる値（ラウンド・リーダーなど） | progress | 方針再検討 N4 |
| 裁定 | ルール文で決着しない点の決定 | 対局の ruling、定義の rulings | #15 |

### 対局の層

| 概念 | 定義 | 実装 |
|---|---|---|
| 対局 | ある版の定義の 1 回のプレイ。人数・着席者・乱数の種 | session.yaml |
| 局面 | 各部品の置き場・順番・付き先・状態、進行、既知、裁定、結果 | 記録から作り直す |
| 基本の操作 | move・attach・flip・rotate・set・shuffle・gather・spread・roll・know・progress・advance・ruling・reset・end | log.jsonl |
| 記録 | 操作の列（アクションの印、操作者、理由のルール） | log.jsonl |
| 見え方 | 1 人のプレイヤーから見た局面と指標と記録 | view・log --as |
| キーパー | すべてを見て、ルールに従って操作し、裁定する立場 | 見え方の player なし |

## 2. 紛らわしい・重なっているところ

| # | 問題 | 推奨 |
|---|---|---|
| R1 | progress（進行の状態）と flow（進行の構造）が重なる。active・phase を両方に書ける | flow を正とし、progress はゲーム固有の値だけにする。flow の active は progress に写すが、phase は写さない（今の実装） |
| R2 | 「アクション」と「基本の操作」の名前が近い | アクション＝ルールに結びついた手順（定義）、操作＝局面を変える 1 回の基本動作（対局）。画面・文書でこの 2 語を使い分ける |
| R3 | 「条件」と「ルール」の関係 | 条件はルール文のうち、構造だけで機械的に確かめられる部分の写し。条件はルールを refs で指し、ルール文を正本とする（条件と文の食い違いは裁定で解く） |
| R4 | 「指標」と「用語」の関係 | 数えられる値は指標、数えられない・比べる・たどる値（最長の街道）は用語。用語から指標を refs で指す |
| R5 | 種類の継承と、区別しない部品（count）の種類 | 区別しない部品も種類を持つ（資源→レンガ）。候補・条件・指標は種類の継承で引く（今の実装） |
| R6 | 既知と公開範囲と表示方法の 3 つで見え方が決まる | 見え方＝公開範囲（エリア）× 表示方法（部品の状態の show）× 既知（プレイヤー）。指標と記録もこの規則に従う（第三弾で記録・指標に広げた） |
| R7 | 「プレイヤー」と「アクター（PRD のエージェント）」と「行う人（--by）」 | 行う人（by）は席かキーパー。PRD のアクターはプロダクトの利用者。定義の中では「プレイヤー（席）」と「キーパー」だけを使う |

## 3. 作ったものとルールの差分（再現できないもの）

カタンのルール R1〜R13、かがり火 R1〜R8、六角の陣取り R1〜R4 を、今の仕組みで再現できるかを確かめた。

| ルール | 再現 | できないところ | 必要な汎用の概念 |
|---|---|---|---|
| カタン R1 準備 | 一部 | 数字のトークンを「6 と 8 を隣り合わせない」「決まった順（渦巻き）」で置く。盗賊を「砂漠のタイル」に置く | **配る順と配る条件**（spread に順番のあるエリアの並びと条件）／**部品のある場所の選択**（where:T-desert） |
| カタン R2 初期配置 | ほぼ | 2 つめの開拓地に接するタイルから資源を受け取る（手で数える） | **選択式と繰り返しの手順**（リンクでつながるタイルの produces を数えて渡す） |
| カタン R3 産出 | 手で | 出目の合計 → 数字の合うタイル（盗賊なし）→ 接する交点の建物 → 持ち主へ 1 枚・都市は 2 枚。毎手番いちばんの手間（エージェントの報告） | **値と式**（ダイスの合計、属性の参照、比較）、**選択式**（数字が合い盗賊のいないタイル → corner でつながる交点の建物）、**繰り返しの手順**（選んだものごとに渡す） |
| カタン R4 7 の処理 | 一部 | 8 枚以上の人が半分を捨てる（枚数の計算）。奪う相手を盗賊のタイルに接する人に限る | **値と式**（半分、切り捨て）、**プレイヤーへの条件**（その人の建物が、盗賊のタイルに corner でつながる交点にある） |
| カタン R5 建設 | できる | ― | 条件（第三弾） |
| カタン R6 交易 | 一部 | 港の 3:1・2:1（場所で費用が変わる）。プレイヤー間の交換の合意 | **行う人への条件**（港の辺に自分の建物がある）、**合意**（複数のプレイヤーの承認） |
| カタン R7 発展カード | 一部 | 買った手番には使えない。最長交易路（5 本以上の最長の道）。最大騎士力（3 枚以上で最多） | **時間の記憶**（部品がエリアに入った手番）、**グラフの指標**（最長の路）、**比べる指標**（最大・最多・しきい値） |
| カタン R8 勝利 | 一部 | 自分の手番に 10 点以上で勝ち、の検出 | **終了の検出**（指標の条件で警告・提案） |
| カタン R9〜R13 効果 | できる | 発展カードを使うことと効果のアクションのつながりは保証しない | **連鎖**（アクションの後に続くアクション） |
| かがり火 R4 | できる | 守りの有無で働きが変わる（アクションを 2 つに分けた）。火に薪がない人は選べない | 条件（分けたアクションに require）、**プレイヤーへの条件** |
| かがり火 R8 | できる | 山札が 0 枚で終わる、の検出 | 終了の検出 |
| 六角 R2 | 一部 | 駒を「隣の」空いたマスへ（動かす駒の今の場所を基準にした条件） | **ほかの引数の位置を参照する条件**（{piece} のあるマスに linked） |
| 六角 R4 | 手で | 3 つが隣どうしでつながったら勝ち | グラフの指標（連結の大きさ） |

## 4. 必要な汎用の概念（提案）

上の差分から、作品をまたいで効く概念に分けた。番号は優先度の順（効く範囲と手間の削減が大きい順）。

| # | 概念 | 中身 | 効くところ | 境界（ルールの自動実行との関係） |
|---|---|---|---|---|
| G1 | **選択式（クエリ）** | 条件（第三弾）を「選ぶ」側に使う：条件を満たすエリア・部品・プレイヤーの集まり。部品のある場所、リンクでつながる先、属性・状態の値 | 産出、奪う相手、配置、勝利の検出、候補 | 構造の問い合わせだけ。判断はしない |
| G2 | **値と式** | ダイスの合計、属性・状態・指標の参照、比較（=, ≥）、四則と切り捨て | 産出、7 の処理、勝利 | 計算だけ |
| G3 | **繰り返しの手順（導出手順）** | アクションの手順の each に選択式を書く（選んだものごとに操作） | 産出、初期配置の資源、独占 | 宣言した手順を行うだけ。合法かは判断しない（任意で使う） |
| G4 | **引数・プレイヤー・行う人への条件** | ほかの引数の位置を参照する条件、プレイヤーの引数の条件、行う人の条件 | 奪う相手、隣のマスへ、港の費用 | 警告と候補の絞り込み |
| G5 | **時間の記憶** | 部品がエリアに入った手番、手番の中の出来事を局面に残し、条件で参照する | 買った手番に使えない | 記録から導ける |
| G6 | **比べる指標とグラフの指標** | 最大・最多・しきい値、最長の路、連結の大きさ | 称号、勝利の検出 | 構造の計算だけ。称号を渡すのはアクション |
| G7 | **終了の検出** | flow に「指標の条件で終わりを知らせる」を書く（警告・提案。終了の記録はキーパー） | 勝利、山札切れ | 知らせるだけ |
| G8 | **誘発と連鎖** | ある操作・出来事（出目 7）で、ほかのプレイヤーの対応や続くアクションを促す | 7 の捨て札、発展カードの効果 | 促すだけ |
| G9 | **合意** | 複数のプレイヤーの承認を要するアクション（交換） | 交換、交渉 | 承認の記録 |
| G10 | **配る順と配る条件** | spread にエリアの並び順（渦巻き）と条件（隣り合わない） | 数字のトークン | 構造の手順 |

G1〜G3 は、ルールの自動実行に最も近い。RUL-001 #26・#31（目的は定義、機械化しすぎない）との線引きとして、**宣言した手順を、頼まれたときに行う**（エージェントや人が「産出する」を押す）にとどめ、**いつ行うかを自動で決めない**ことを推奨する。

## 5. エージェントの対局から分かったこと（第三弾で対応したもの）

| 報告 | 第三弾の対応 |
|---|---|
| リンクが局面に出ない（自前の補助スクリプトを書いた） | bg near、show --links |
| 距離の決まり・つながりの検査がない | 条件（require）、候補（bg candidates・画面の ✓） |
| 段階の切り替えを毎回手で打った | 進行の構造（flow、advance、画面の「次のフェーズへ」） |
| act が出目や引いたものを返さない | act の done（行った人の見え方で） |
| 局面の出力が 21〜25KB | show --compact（7.8KB） |
| log・指標に見え方がない（買ったカードが見える） | log --as、見えないエリアを数える指標は示さない、vp-total は持ち主だけ |
| 盗賊で発展カードまで奪えた | 選び方に種類の絞り込み（kind: resource） |
| 産出の「行う人」がずれる | 銀行（キーパー）が行い、受け取る人を選ぶ |
| 交換が原子的でない | trade-players アクション |
| ruling の未知のキーが捨てられた | 捨てない |
| 対局の途中で定義が変わった | 定義のハッシュを対局に残し、変わったら警告 |
| 取り消しがない | bg undo（アクションなら全部） |
| 発展カードの効果・数字の置き方が書かれていない | ルール R9〜R13、R1 に追記 |
| 産出を毎手番手で打つ | 未対応（G1〜G3） |
