# SPC-001：ライブラリは、ゲーム定義のファイルを読み込み、各要素を ID で取り出せるオブジェクトとして保持する

## Description

ゲーム定義の要素：ゲームの見出し（ID・名前・概要・人数・版・出典・未決）、陣営、プレイヤー（席）、種類、部品（エリア・オブジェクト）、リンク、組、進行状態の定義、用語、ルール、裁定。

種類・部品・局面の 3 段に分ける（判断の記録 G2）。種類はエリアかオブジェクトか別の種類を元にする。部品は種類と変わらない属性の値と初期の置き場を持つ。区別しない部品は個数で持てる（判断の記録 G14）。

ルールは本文（自然文）を正本とし、区分・参照・出典を持つ。

ID は要素の種類をまたいで一意とする（ルールの参照に型がないため）。種類と同じ名前の部品は、部品の側に接尾辞を付ける（例：種類 paranoia の部品 paranoia-pool）。部品は持ち主（owner。プレイヤーの ID）を持てる。持ち主は裏から分かる情報に使う（SPC-011）。（第一弾のレビュー C1・C9）

## Acceptance Criteria

- **AC-001-1**
  - **Given** 三目並べのゲーム定義のファイル（プレイヤー 2、マス 9、ルール 4）
  - **When** 開発者がライブラリでファイルを読み込む
  - **Then** プレイヤー X・O、エリア c11〜c33、ルール R1〜R4 を、それぞれの ID で取り出せる
- **AC-001-2**
  - **Given** 同じ ID のルールが 2 つあるゲーム定義のファイル
  - **When** 開発者がライブラリでファイルを読み込む
  - **Then** 読み込みは失敗し、重複した ID とその 2 か所が示される
- **AC-001-3**
  - **Given** 略記（プレイヤーの人数分に部品を作る書き方）を使ったゲーム定義のファイルと、人数 2
  - **When** 開発者がライブラリでファイルを読み込み、展開した形を求める
  - **Then** 略記が人数分に展開され、各部品を個別の ID で取り出せる
- **AC-001-4**
  - **Given** 部品「M-INT1」の持ち主を「M」とした定義
  - **When** 開発者がライブラリで部品 M-INT1 を取り出す
  - **Then** 持ち主 M が示される
