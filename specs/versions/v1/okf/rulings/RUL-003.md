# RUL-003：カタンの再現と、手札の並び順について

## Exchanges

| # | 話者 | 内容 |
|---|---|---|
| 1 | 利用者 | カタンの再現もしてみて |
| 2 | 利用者 | 手札の並び順に意味がある場合もある |
| 3 | 利用者 | （/goal）カタンの再現後、エージェントのプレイが可能かの確認、概念定義の再レビュー、第三段改善を進めて |
| 4 | 利用者 | 文字多すぎてわからん。全ての情報を可視化に出すかは選べるようにしたほうがよい。オブジェくとやエリアを選択時のみ出す情報があってもいい |
| 5 | 利用者 | 騎士とか、自分の都市の数とか、情報的なものとかの概念も考えてね |
| 6 | 利用者 | フェーズとか、手番の概念化もお願い。フリーアクションとかメインアクションとか。自由度を考えて定義できるようにして |
| 7 | 利用者 | 作ったものとルールの差分から再現できないものの確認と、その再現に必要なものを考えたうえで汎用化された概念として考えて |

## Results

| 発言 | 行き先 | 結果 |
|---|---|---|
| #1 | 開発ルール | 既存ゲーム（カタン）を定義で再現し、作ったものが対応できるかを確かめる。定義は公開しない（RUL-001 #37）ので local/ に置く。足りない仕組み（六角の頂点・辺の置き場、ダイス、マスへの配布、ランダムに取る）を汎用の形で足す。反映：SPC-046 r1・SPC-047 r1 |
| #2 | 設計への指定 | エリアは並び順を持てる（ordered）。順番を持つエリアの中では、部品を並べ替えられる。対象：SPC-004・SPC-028。反映：SPC-048 r1 |
| #3 | 開発ルール | エージェントがカタンを遊べるかを確かめ（サブエージェントに bg コマンドと定義だけで遊ばせる）、概念定義を再レビューし、第三段の改善を進める |
| #4 | 設計への指定 | 画面に出す情報（ID・状態・公開範囲・縦横の印・エリアの ID と持ち主・見えない理由・操作の説明）を見る人が選べるようにし、既定は名前だけにする。詳しい情報は部品・エリアを選んだときに調べる欄に出す。対象：SPC-027・030・031。反映：SPC-049 r1 |
| #5 | 設計への指定 | 局面から数えて出す値（指標）を概念に足す。例：使った騎士の数、自分の都市の数、勝利点。部品の種類・置き場・持ち主・属性・状態で数え、重みを付けて足し合わせる。隠れた部品を数える指標は持ち主にだけ見せる。つながりをたどる値（最長の街道など）は用語の自然文に残す。対象：CTR-F-001 r1（ゲーム定義の形式の概念モデル）。反映：SPC-050 r1 |
| #6 | 設計への指定 | 進行の構造（段階・巡・手番・フェーズ）と、アクションの区分（メイン・フリー・手番外の対応）、回数の上限、手番の順（席順・往復・逆順）を、定義で自由に組めるようにする。対象：CTR-F-001 r1（ゲーム定義の形式の概念モデル）。反映：SPC-051 r1 |
| #7 | 調査 | 作ったもの（定義・ライブラリ）とルールの差分から、再現できないものを洗い出し、再現に必要なものを汎用の概念として考える。結果は概念定義の再レビュー（notes/concept-review.md）に書く |
