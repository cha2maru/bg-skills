# RUL-013：割り込んで応じる行為（スタック・キュー）について

## Exchanges

| # | 話者 | 内容 |
|---|---|---|
| 1 | 利用者 | 新たなボードゲームを作るときに役立つスキルを考えて |
| 2 | 利用者 | カードゲームのようなプレイヤーの行動に他のプレイヤーが割り込んでアクションするようなスタックやキューのような概念を定義できるようにして |
| 3 | 利用者 | つくってよい |

## Results

| 発言 | 行き先 | 結果 |
|---|---|---|
| #1・#3 | 開発ルール | スキル 5 つを .claude/skills/ に作った（bg-design・bg-playtest・bg-balance・bg-hidden-info-audit・bg-rules-audit）。bg-design で架空のカードゲーム「ルーン決闘」（examples/rune-clash.yaml。スタックを使う）を作り、そこで見つかったエンジンの不足を直した：アクションの cost（積むときにすぐ行う手順）、メインにも手番外の対応にもあるアクションは手番の人でなければ対応として扱う、解決待ちがある間は進行を進めない。bg-playtest でエージェントに遊ばせ（25 手番）、見つかった点を直した：手順の if の式で {引数} が埋まらず雷撃が効かなかった（エンジン）、席の中の手札の持ち主が親から引き継がれず本人にも見えなかった（子のエリアは親の owner を引き継ぐ）、bg log --as が今の局面で伏せていて配った札が後で分かった（操作の直後の局面で伏せる）、選ぶものが足りない呪文を積めた（積む前に確かめる）、スタックの候補が番号だけ（誰の何かを添える）、--only stack に見送り待ちを含める、次に解決するものに next、積んだ本人の見送りに注意、bg resolve --by、ルーン決闘に引き分けで終えるアクション |
| #2 | 設計への指定 | スタックを、新しい原型にせず、操作（時間の中の出来事）の派生として作った。アクションの stack: true は、行うと手順を行わずに解決待ちの列（局面の stack）に積む。ほかのプレイヤーは応じて積む（割り込み）か、pass で見送る。積んだ人以外の全員が見送ると、一番上（flow.stack: fifo なら一番下）を解決する（手順を 1 つずつ行い、行えなければ立ち消え）。cancel で解決待ちを打ち消す（引数の stack: true が候補）。スタックがある間、積まないアクション（during_stack でない）は警告（厳格なら拒否）。式 stack()、見え方の stack・stack_waiting・stack_done、bg pass・bg resolve、画面のスタックの帯と見送るボタン。反映：SPC-068 r1、CTR-F-001 r1（追加だけ） |
