# RUL-021：Claude Code のプラグインにすることについて

## Exchanges

| # | 話者 | 内容 |
|---|---|---|
| 1 | 利用者 | claude plugin 化をすすめて |

## Results

| 発言 | 行き先 | 結果 |
|---|---|---|
| #1 | 開発ルール（配り方） | リポジトリのルートをプラグイン兼マーケットプレイスにした（okf-specs と同じ形）。`.claude-plugin/plugin.json`（bg-skills 0.1.0。版は pyproject と揃える）と `marketplace.json`（source `./`）。スキルは `skills/` へ移し、リポジトリの中で使うための `.claude/skills` は `skills/` へのリンク。`bin/bg` は `uv run --project <プラグインのルート> bg` を呼ぶ（Claude Code がプラグインの bin を PATH に入れる。作業フォルダはそのままなので、定義・対局は利用者のプロジェクトに置ける）。スキルの中のパス（examples・specs・CLAUDE.md）は「プラグインのルート（スキルのディレクトリから 2 つ上）」から読むと注記し、ほかのプロジェクトではエンジンを直さず報告にとどめる。配るときは git から入れる（追跡するファイルだけが入る）。フォルダのパスから入れると、git の管理外の local/（市販品の定義）・sessions/・.venv までコピーされるので、自分の PC の中だけにする（推奨で決めた。RUL-018）。LICENSE は利用者が決める（未決。公式のディレクトリに出すときに要る）。形：.claude-plugin/plugin.json 0.1.0（概念は起こさない） |
