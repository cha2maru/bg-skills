# RUL-023：カードとトークンの見た目、得点の表し方、桜降る代に決闘をの調査について

## Exchanges

| # | 話者 | 内容 |
|---|---|---|
| 1 | 利用者 | カードとトークンで見栄えがある程度変わってほしい |
| 2 | 利用者 | 得点計算をエリアのマス移動で示す、即時得点、特定のタイミングで計算するなどを表現できるようにしてほしい |
| 3 | 利用者 | さくらふるよにけっとうをというゲームについて調べて |

## Results

| 発言 | 行き先 | 結果 |
|---|---|---|
| #1 | 設計への指定 | 種類の既存の項目 shape の値を増やした（round・disc・cube・pawn・tile。card か無しはカード。項目は増やさない。CTR-F-001 の版は据え置き）。形のある部品はトークンとして、持ち主の色（なければ種類の色）の立体の駒で描く。カードは紙の札（上端に種類の色の帯、影）。数える部品の札には形の印を付ける。見え方の数える部品にも shape を出す。（推奨で決めた。RUL-018）反映：SPC-064 r1（表示だけ） |
| #2 | 設計への指定 | 既存の項目だけで書けることを、手本 examples/harvest-road.yaml（架空「収穫の道」）で示した。マスの移動で示す得点＝道のマス（pos で卓の周りに並べた子エリア）と駒。得点は名前つきの式 score（駒のあるマスの番号）。即時得点＝アクションの let で行き先のマス（cell(score(actor) + 値)）を決め、駒を move。決まった時機の得点計算＝手番の on_end で「巡の終わり（最後の席）」を if で選び、プレイヤーごとに進める。終わりの得点計算＝指標 final（道の得点＋組の点）と flow.scoring（by: final、tiebreak: score）と end_when の winners: scoring・timing: round_end。画面では、マスの多い盤（20 以上）を小さなマスで描く。形式の項目は増やしていない（RUL-016 の 6）。反映：SPC-064 r1（表示）、notes/endgame/gates.md |
| #3 | 調査 | 英語版 Sakura Arms のルールブック（AEG）と 4Gamer の記事で調べた。2 人用の決闘のカードゲーム（BakaFire Party。桜花結晶のトークンが、間合・オーラ・ライフ・フレア・ダストの間を動くことが局面のすべて）。市販品なので定義は作らず、作るなら local/ に置く（RUL-001 #37）。トークンが置き場の間を動くことで状態と勝ち負けを表す作品で、数える部品・置き場の上限（capacity）・手順の move で書ける見込み。 |
