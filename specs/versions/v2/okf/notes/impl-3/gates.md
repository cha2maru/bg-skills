# 判断の記録：カタンの再現と手札の並び順（2026-11-19）

利用者の発言 RUL-003 #1「カタンの再現もしてみて」・#2「手札の並び順に意味がある場合もある」による。推奨案（Claude の判断）で決めた。

| # | 判断 | 理由 | 要件 |
|---|---|---|---|
| L1 | カタンの定義は local/catan.yaml（git 管理外）。ルールの文は要約、絵柄・名称の素材は使わない。テストは定義があるときだけ動く | RUL-001 #37（既存ゲームの定義は公開しない） | — |
| L2 | 六角の頂点・辺は、マスの子エリアとして生成し、xy（マスの大きさ 1 の平面）と辺の角度を持つ。リンクの種類は corner・side・end・adjacent | 開拓地（頂点）・街道（辺）の置き場と、距離の決まり（隣の頂点）を表すため | SPC-046 |
| L3 | ダイスは「状態を取りうる値からランダムに選ぶ」操作 roll。乱数は種と通し番号から | 再生で同じ結果 | SPC-047 |
| L4 | random:<エリア> は区別しない部品（手札の資源）も 1 枚ずつ数えて選び、記録には選んだ部品の ID（と n: 1）を残す | 手札からランダムに 1 枚取る | SPC-047 |
| L5 | spread は from の部品を into の子へ 1 つずつ順に配る。数字のトークンの「砂漠を避けて置く」は書けないので手で置く | 手順に条件を入れない（K8） | SPC-047 |
| L6 | gather に owner（持ち主）での絞り込みを足した。箱からの準備で、プレイヤーごとのコマを手元へ配るため | 箱から始めると、資源・コマの配置も準備の手順に要る（テストで抜けが見つかった） | SPC-043 |
| L7 | エリアの ordered で並び順に意味を持たせる。画面では順番を持つエリアの中のカードに落とすとその位置に入れ、重ねるのは Alt | RUL-003 #2 | SPC-048 |
| L8 | 手札に区別しない部品（資源）があるとき、見せない相手には種類ごとの数を出さず、合計の枚数だけを出す | 実装中に見つかった漏れ（他人の手札の資源の内訳が見えていた） | SPC-011 |
| L9 | 六角の盤の中のつながり（自動で作るリンク）は、画面で線を描かない | カタンで 441 本の線が盤を覆った | SPC-032 |
| L10 | カタンの対局を 8767 で公開した（箱から準備済み） | 利用者が見て確かめられるように | — |

## カタンで見つかったこと（課題）

| # | 課題 | 変更案 |
|---|---|---|
| E1 | 他人の手札の資源の内訳が見えていた（直した。L8） | SPC-011 の受入基準に、区別しない部品の内訳を隠すことを足す |
| E2 | 箱から始めると、準備の手順に資源・コマ・ダイスの配置まで要る。手順の抜けがテストで見つかった（目的どおりの働き） | 変えない。準備の確かめ（setup-check）を、箱から始めた対局でも使う |
| E3 | 数字のトークンを「砂漠を避けて、決まった順に」置く手順は書けない（条件と順番） | 手順の条件は入れない方針のまま、spread に「埋まっていない／特定の種類の部品があるマスを避ける」の絞り込みを足すかを検討 |
| E4 | 建てる費用の支払いは手順で書けるが、払えないとき（資源が足りない）はアクション全体が受け付けられないだけで、理由が分かりにくい | エラーの文に、どの手順で何が足りないかを出す |
| E5 | 産出（出目に合うタイルに接する建物の持ち主へ資源）は、接するもの（リンク）を数える導出で、手で行う必要がある | 用語（接する交点）は定義済み。エージェントが導出する。ライブラリに「あるエリアにリンクでつながるエリアの部品」を引く問い合わせを足すと、エージェントが楽になる（逆引きの拡張） |
| E6 | 港（海の辺の交換所）を書いていない | 盤の外周の辺に置く部品として足せる（定義の追加だけ） |
| E7 | 画面で六角のマスのタイル・トークンは小さく、マスの印（▾）が邪魔 | 六角のマスでは折りたたみの印を隠す |

## 追加：表示の切り替えと指標（2026-11-19）

| # | 判断 | 理由 | 要件 |
|---|---|---|---|
| L11 | 画面の「表示」で、部品の ID・状態・公開範囲・縦横の印・エリアの ID と持ち主・見えない理由・操作の説明を切り替える。既定はどれも出さない。カードの形と山の枚数は常に出す。選んだカードは状態を出す | RUL-003 #4「文字多すぎてわからん」 | SPC-049 |
| L12 | 指標は count（種類・置き場・持ち主・属性・状態、sum_attr で属性の値の合計）と sum（重みつきの合計）。局面には保存しない | RUL-003 #5。数えるのは構造だけで決まる（#31 の範囲） | SPC-050 |
| L13 | 隠れた部品を数える指標は、その値を見えない人に出さない。手札の枚数のように枚数だけ分かればよい指標は needs: count | 勝利点カードを漏らさない／手札の枚数は公開 | SPC-050 |
| L14 | 最長の街道・最大騎士力の持ち主のように、つながりをたどる・比べる値は指標にせず、用語とルールの自然文に残す | 機械化しすぎない | SPC-050 |
| L15 | 定義で badge: true の指標だけを席の名前の横に出し、全部は「指標」タブで見る | 文字を増やしすぎない（L11） | SPC-050 |
| L16 | エージェントの対局（サブエージェント）の途中で、カタンの定義に指標を足した。部品は変えていないので記録の再生に影響しない | 並行作業 | — |
