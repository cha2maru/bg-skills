## 追加：画面（コンポーネントとルールの可視化）（2026-11-18）

利用者の依頼「コンポーネントとルールについての可視化も作って。TTS みたいに操作ができるだけでゲームエンジンでなくてもいい。定義した結果どうなったかをみれ、さわれ、触った結果がログにのこればよい。マウス操作可能、エージェントからも操作可能にして」。

| # | 判断 | 理由 |
|---|---|---|
| I29 | `bg serve` で標準ライブラリの HTTP サーバーを立て、依存なしの 1 ファイルの画面（ui.html）を出す | 依存を足さない。描画には凝らない（#21） |
| I30 | 画面の操作は `POST /api/op` で、`bg op` と同じ `Session.apply` を通す。記録は 1 つ（log.jsonl） | 「触った結果がログに残る」「エージェントからも操作可能」を 1 つの経路で満たす |
| I31 | 画面は 1.5 秒ごとに記録の件数を見て、変わったら読み直す（エージェントの操作を拾う） | 最小の同期。WebSocket は使わない |
| I32 | 記録への追記を flock で排他にし、読む・確かめる・足すを 1 つにする | 画面とエージェントが同時に書いても古い局面に対して受け付けない |
| I33 | ドラッグは HTML5 の DnD ではなくポインタ操作で作る | 自動のブラウザで実際のマウス操作として確かめられ、タッチでも動く |
| I34 | 落とした先がカードならその上に重ね、Shift を押していればその下に差し込む。エリアならそのエリアへ | 重ね置き（#12）と差し込み（#20）を 1 つの操作で選べる |
| I35 | 「見る立場」でキーパー・各プレイヤーの見え方を切り替え、「操作する人」「理由のルール」を操作に付ける | 見え方（SPC-011）と記録の操作者・理由（SPC-015）を画面から使う |
| I36 | 172.29.127.192（WSL の内側のアドレス）で公開した。認証はない | 利用者の指示。0.0.0.0 にはしない |
