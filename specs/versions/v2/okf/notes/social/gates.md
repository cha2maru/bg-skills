推奨案で進めた（人の確認をはさまない）。

## 判断

| # | 判断 | 理由 | 退けた案 |
|---|---|---|---|
| D1 | 発言は新しい原型にせず、操作 say（物を変えない操作）にする | RUL-005 #2（派生で表せないものだけを足す）。発言は時間の中の出来事で、操作の原型に入る。真偽を判定しないのは RUL-001 #31 と同じ | 発言の原型、チャット欄を記録の外に置く（エージェントの振り返りに使えない） |
| D2 | 話せる・話せないは、進行の段階・フェーズの talk（真偽か式）で宣言し、外れたら警告 | 作品ごとの縛り（花火・人狼の夜・ディプロマシーの命令中）が、時間の区切りと話し手・聞き手で書けた | 発言の種類ごとの許可表（作品をまたいで書き方がばらばら） |
| D3 | 封をした選択（命令・投票）は、紙のオブジェクトに書き込む状態（型 text・player）＋伏せる＋一斉に開くアクション | 実物も紙に書いて伏せる。新しく要ったのは「値の並びでなく型を持つ状態」だけ | sealed・reveal の操作（物の外に値を持つことになる） |
| D4 | 一部だけの知識は know の fields | 既知（know）の細かい形。占い（陣営だけ）とヒント（色か数）の両方に効いた | 札ごとのヒントの状態（作品ごとに状態を足すことになる） |
| D5 | 非公開の行為はアクションの secret（記録の見え方） | 夜の行動は、局面の物（襲撃の印）は公開範囲で隠せるが、記録の操作（誰が誰を）が漏れる。記録の見え方の問題 | 夜の行動をキーパーに口頭で伝える（記録に残らない） |
| D6 | 守られる約束（提案と合意で、まとめて行う）は今回は作らない | 3 作とも要らなかった（ディプロマシーの約束は守らなくてよい、人狼は投票）。カタンのプレイヤー間の交換で必要になる | 先に作る（使う作品がない） |
| D7 | ディプロマシーの命令の解決（支援・切断・輸送）は自動にしない。キーパーが規則（R4〜R8）で駒を動かし、隣でない移動は警告 | RUL-001 #31。命令の文は自由文で、解決はルールの中身 | 解決の自動化 |
| D8 | ディプロマシーの地図は、外のパッケージから取れなかったので、標準の地図を知識から書き、規則で検証した（陸 42・海 19・内陸 14、内陸に艦隊の境なし、海に陸軍の境なし、沿岸は海に面する、ミュンヘン・北海・イオニア海・中部大西洋の隣接） | データの誤りを機械的に見つける | 未検証のまま使う |
| D9 | 位置の見える駒が要る地図のために、絵のない rect の配置（aspect）、プレイヤーの color、種類の show_state、エリアの folded を足した（表示方法） | 3 作の画面で、どの国の駒か、生死、命令の文が読めなかった | 作品ごとの画面 |
| D10 | 守られる約束は、新しい原型にせず発言 say の派生（offer：受けたらまとめて行う操作のリスト）と操作 answer にした。受けると中身をすべて行うか 1 つも行わない。中身に入れられるのは物を動かす・状態を変える操作だけ | 実物も「言って、うなずいて、渡し合う」。まとめて行うのはアクションと同じ（全部か無し）。状態は発言に持たせ、局面の物は増やさない | 提案のオブジェクト（紙）を置く（物でない約束を物にしてしまう）、アクションに組み込む（作品ごとに交換のアクションを書くことになる） |
| D11 | 発言が多い対局のために、bg show --compact の talk は最後の 10 件と受付中の提案だけにし、各件に番号 n（bg answer で使う）を付けた。--talk-since N でその番号から出す。省いた件数は talk_omitted に出す | エージェントは毎手番 show を読むので、議論が長いと局面より発言が大きくなる。番号を付けたのは、省くと並びの位置で数えられなくなるため | 発言を別のコマンドに分ける（読む回数が増える）、要約する（中身を変えることになる） |

## 再現で見つけて直したエンジンの不具合

| 症状 | 直し方 |
|---|---|
| 指標の式から metric() でほかの指標を引くと、計算し直しが止まらない（ディプロマシーの調整の数） | 指標の計算の中では計算済みの値を使い、自分を引いても止まるようにした |
| 発言の to（聞かせる相手）を置き場として上限を確かめて落ちる | 上限の確かめは、置き場への操作だけ |
| YAML の誤りで bg check が traceback | 1 行のエラーで返す |
| 見える部品の見え方に属性が出ない（花火の札の色と数）、--compact で別の札がまとまる | 見え方に attributes を出し、まとめる鍵に含めた |
| 式で文字列のメソッド（'・'.join など）を書いてしまう | 関数 join を足した（bg check がメソッドの呼び出しを指摘する） |

## 再現できていないところ（ルール文で決着する・キーパーが行う）

- ディプロマシー：命令の解決、撤退先の制限（押し出した駒の来た州）、輸送の経路の確かめ、増産の数の上限（調整の指標は出す）
- 人狼：役職の構成の変種、昼の議論の時間（決選投票は、ループ 6 で名前つきの式 leaders と進行状態 runoff で書いた）
- 花火：否定の情報（「この札は赤ではない」）は、ヒントの発言の文（左から何枚目）から各自が読み取る。最後の 1 巡の数え方は知らせ（signal）だけ
