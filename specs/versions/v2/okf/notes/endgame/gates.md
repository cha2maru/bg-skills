# 終わり方と複雑なルール（RUL-015）：検討と判断

利用者の「ルールとかの複雑さ、勝利条件、敗北条件、終了時得点計算、ターン終了ルールなど、ボードゲームの複雑そうなルールと定義について検討して」（2026-11-19）への対応。推奨案で進めた。

## 型ごとの書き方

| 型 | 例 | 書き方 | 状態 |
|---|---|---|---|
| すぐ勝つ・負ける | 精霊獣デュエル（サイドを取り切る・場が空・山札切れ）、ルーン決闘（10 ダメージ） | `flow.end_when` の 1 件に `winners: 式` か `losers: 式`（式の値は `value`）。`flow.auto_end: true` なら満たした操作のあとに結果を記録して終える | 今回足した |
| 巡の終わりまで続ける（全員が同じ回数） | 誰かが 10 点に届いたら、その巡を終えて終わる | `timing: round_end`（ほかに `turn_end`・既定 `now`） | 今回足した |
| 終わりの得点計算 | 点の多い人の勝ち | `flow.scoring: {by: 指標, tiebreak: [指標…], low: false}`、終わりの条件に `winners: scoring` | 今回足した |
| 同点 | 同点ならお金の多い人、なお同じなら分け合う | `tiebreak` の並びで比べ、なお同じなら同じ順位（両方の勝ち） | 今回足した |
| 引き分け | 決めた手番で終わらない | 終わりの条件に `draw: true`、手順は `{op: end, draw: true}` | 今回足した（以前は書けなかった） |
| 同時に満たす | 自分のサイドを取り切ったのと同時に相手の場も空 | `end_when` の並びが優先の順（上のもの） | 今回足した |
| 協力ゲーム（全員勝ち・全員負け） | — | `winners: "players()"` か `losers: "players()"` | 今の形で書ける |
| チームの勝ち | 人狼（陣営） | `winners:` の式で陣営の人を並べる | 人狼に書いた |
| 手番の終わりの処理 | 手札の上限まで捨てる、片づけ、維持費 | 手番の `on_end`（手番の人はまだ前の人。`active()` で読む）。段階の `on_end` も | 今回足した |
| 手番の初めの処理 | どく・やけど、マヒが解ける | 手番の `on_start`（既存。ループ 10 で stepwise） | 既存 |
| 得点の計算そのもの | セット集め、多数派、最長の路 | 指標（`count`・`sum` の重み・`expr`）と名前つきの式 `functions` | 既存 |
| 隠れた得点 | 伏せた勝利点のカード | 指標の見え方を守る。見えない得点があれば、プレイヤーには順位（`standings`）を出さない | 今回足した |
| ルールの複雑さ | ルールの数・条件・式の大きさ・機械で確かめないルール | `bg complexity` | 今回足した |

## まだ自然文に残るもの（次の候補）

- 途中で脱落して、残りの人で続ける（多人数の脱落）。今の `losers` は対局を終える
- チェックメイト・ステイルメイトのように、指せる手をすべて調べないと決まらない終わり方（`bg selfplay` のように候補を全部数えれば書けるが重い）
- カードの文が基本のルールを上書きする（「このカードはルール R3 を無視する」）。例外は自然文と裁定
- 終わりの条件が満たされた後に、最後の 1 手番だけ全員に与える（「最後の 1 巡」）は `round_end` で近いが、満たした人の次から 1 周は書けない

## 判断

| # | 判断 | 理由 | 退けた案 |
|---|---|---|---|
| E1 | 終わりの結果は、終わりの条件に書く（winners・losers・draw・scoring）。自動で終えるかは flow.auto_end で作品が決める | 結果の決め方は条件と一緒に読むのが自然。キーパーが確かめてから終えたい作品（人狼の役職公開）もある | 終わりの条件は文だけにし、結果はいつもキーパー（selfplay・ボットで勝敗が数えられない） |
| E2 | 時機（timing）は、条件を満たしているかをその時機に調べる。途中で満たして時機までに外れた場合は終わらない | 多くの作品で、得点は減らないので同じ。記憶する仕組みを足さずに済む | 満たした時点で「終わりの予約」を局面に持つ（得点が減る作品で必要になったら足す） |
| E3 | 得点の順位は指標から作り、見えない値があればプレイヤーには出さない | 隠れた勝利点から順位が漏れない（bg-hidden-info-audit の 7） | 順位はいつも全員に出す |
| E4 | 手番の終わりの手順（on_end）は、手番の人が前の人のまま行う | 「手番の終わりに、手番の人は手札を 7 枚まで捨てる」を active() で書ける | 次の手番に入ってから行う（誰の手番の終わりか分からない） |

## 得点の表し方（RUL-023。手本 examples/harvest-road.yaml）

| 型 | 書き方 |
|---|---|
| マスの移動で示す得点（得点の道） | 道のマス＝子エリア（pos で並べる。順番が得点）。駒＝種類の shape: pawn。得点＝名前つきの式（駒のあるマスの番号） |
| 即時得点 | アクションの let で行き先（cell(score(actor) + n)）を決め、駒を move |
| 決まった時機の得点計算 | 手番・段階の on_start・on_end。巡の終わりは on_end の if（active() が最後の席） |
| 終わりの得点計算（道に出さない得点） | 指標（式）で足し、flow.scoring の by。end_when の winners: scoring |
| 数える部品の得点（勝利点トークン） | 数える部品を置き場へ move（tests/test_endgame.py の RACE） |
