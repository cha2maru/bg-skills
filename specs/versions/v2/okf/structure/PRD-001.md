# PRD-001：bg-skills

ボードゲームの情報群を抽象化・操作し、新作・既存作のテストプレイとバランス調整をエージェントが行える汎用環境。

## Purpose

本PJではボードゲームの情報群の抽象化、その操作を行い、新たなボードゲームや既存のボードゲームのテストプレイやバランス調整をエージェントにて行えるようにする汎用的な環境の開発を目指す（利用者の発言。2026-11-18）。

## Actors

| アクター | 説明 |
|---|---|
| ゲーム設計者 | ゲームを設計する人。個人（1 人）の設計者が、手元の WSL2 で、エージェントと一緒に使う（推奨で決めた。RUL-018） |
| エージェント | Claude Code のエージェント（サブエージェントを含む）。bg コマンドとスキルで、定義を書き、遊び、測る（推奨で決めた。RUL-018） |
| 他の開発者 | このリポジトリの作者（1 人）。ほかの開発者に配ることは当面しない（推奨で決めた。RUL-018） |

利用者の発言は「ゲームを設計、エージェント、他の開発者など」（2026-11-18）。「など」のため、ほかの立場がありうる。ほかのアクターは置かない。画面で遊ぶ人はゲーム設計者に含める（推奨で決めた。RUL-018）

## Scope and Out of Scope

対象：ゲーム定義の形式、対局（記録・見え方・進行・機械の層）、確かめの道具（check・fuzz・selfplay・quiz・playstats・complexity）、画面、TTS への書き出し、スキル。対象外：ネット越しの対戦と認証、公開サーバ、市販品の定義の公開、ルールの完全な自動裁定（推奨で決めた。RUL-018）

## Glossary

| 用語 | 意味 |
|---|---|
| ゲーム定義 | ゲームを構成する情報の YAML。形式は CTR-F-001 |
| 原型 | 定義の概念の土台。エリア・オブジェクト・リンク・プレイヤー・ルールと用語・操作・式・進行の 8 つ |
| エリア | 物を置く場所（盤・マス・手札・山など） |
| オブジェクト（部品） | 置かれる物（カード・駒・トークンなど） |
| 局面 | 対局のある時点の、部品の置き場と状態と進行 |
| 記録 | 対局の操作の並び（log.jsonl）。局面は記録から作る |
| 見え方 | 局面を 1 人のプレイヤーから見たもの |
| シナリオ | 対局ごとの非公開の設定（脚本・配役など）。定義に重ねる |

## Design Decisions

| 決定 | 理由 | 退けた案 | 出典・日付 |
|---|---|---|---|
| 定義に現れるものは原型（エリア・オブジェクトなど 8 つ）の派生として表し、派生で表せないものだけを原型にする | 利用者の指定 | 作品ごとの概念を足していく | RUL-005 #2・2026-11-19 |
| 中心の契約をゲーム定義の形式（CTR-F-001）とし、概念モデルをその本文に置く | 利用者の指定（概念の定義を重視） | 実装の構造を中心にする | RUL-004 #5・2026-11-19 |
| ルールの中身は自然文を正本とし、機械化するのは参照・置き場・乱数・見え方・進行・条件の警告まで | 目的は定義（機械化しすぎない） | ルールエンジン | RUL-001 #26・#31 |
