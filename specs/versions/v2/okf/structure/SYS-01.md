# SYS-01：bg-skills ライブラリと道具

## Purpose and Scope

ゲーム定義（YAML）を読み、対局の局面を記録から作り、見え方・候補・指標を返す Python のライブラリと、それを呼ぶ `bg` コマンド、卓の画面（ローカルの HTTP）、TTS への書き出し、エージェント向けのスキルを、1 つのリポジトリ（bg-skills）として配る。

含まないもの：ルールの自動実行（合法手の判定は警告と候補にとどめる。RUL-001 #31）、ネットワーク越しの多人数対戦、認証。

## Technology Stack

- Python 3（uv で管理）、PyYAML。ほかの依存は持たない（画面は 1 ファイルの HTML で外部のライブラリを使わない）
- 対象 OS：WSL2 上の Ubuntu（画面は Windows のブラウザから WSL の内側のアドレスで見る）
- 配布：git リポジトリ。`uv sync` で入れる
- 画面の受入の試験：playwright（依存には入れず、`uv run --with playwright`）

## Assumptions

- 対局のフォルダは 1 台の PC の上にあり、同時に書くのは同じ PC の bg コマンドと画面のサーバーだけ（ファイルロックで直列にする）
- 画面のサーバーは WSL の内側のアドレスにだけ公開する（認証がないため）

## Common Policies

| 項目 | 方針 |
|---|---|
| タイムゾーン・日付の基準 | 記録の時刻はローカル時刻の ISO 8601 |
| 命名規約（API パス、テーブル・項目、リソース） | 定義のキーは英語の小文字（ハイフンか下線）、中身（name・text）は日本語。ID は定義の中で種類をまたいで一意 |
| 認証・認可 | なし（ローカルだけで使う） |
| API 共通仕様 | 画面の API は `/api/` の下。JSON。版は持たない |
| エラー応答の形式 | `{ok: false, error: <日本語の文>}`。コマンドは標準エラーに日本語の文、終了コード 1 |
| メッセージ ID の体系 | なし（文で返す） |
| 排他・トランザクション | 記録への追記はファイルロックで直列。アクションは手順をすべて行うか、1 つも行わない |
| ログ | 対局の記録（log.jsonl）がそのまま監査の記録。別のログは持たない |
| 共通項目（テーブル） | なし（DB を持たない） |

## Design Decisions

| 決定 | 理由 | 退けた案 | 出典・日付 |
|---|---|---|---|
| 局面は保存せず、記録を最初から再生して作る | 取り消し・見え方の切り出し・同じ局面の再現が記録 1 つで済む（SPC-017） | 局面のスナップショットを保存する | 第一弾（notes/impl-1/gates.md） |
| 画面はゲームエンジンにせず、部品をさわれる卓にする（記録は bg op と同じ） | 目的は定義で、ルールの自動実行はしない（RUL-001 #26・#31） | 合法手だけを許す対戦画面 | RUL-002 |
| 依存は PyYAML だけ。画面は 1 ファイルの HTML | エージェントの環境で入れる手間を減らす | Web フレームワーク・フロントエンドのビルド | 第一弾 |
